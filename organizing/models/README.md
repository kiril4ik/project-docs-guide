# Organizing Models

> **What:** One page per way of organizing docs. Every page has the same sections: what it looks like → pros/cons → best for → avoid when → how it fails → migrating.
> **Read when:** comparing options. For the side-by-side matrix, see [the organizing overview](../README.md#comparison-matrix).

| Model | One-line summary |
|---|---|
| [by-doc-type.md](by-doc-type.md) | Folders per kind of doc. The intuitive default for small and medium projects. |
| [by-audience.md](by-audience.md) | Folders per reader group. Best when audiences barely overlap. |
| [by-domain.md](by-domain.md) | Folders per business domain or feature. Best when teams own domains. |
| [diataxis.md](diataxis.md) | Tutorials / how-to / reference / explanation. Best for product and user docs. |
| [by-lifecycle.md](by-lifecycle.md) | Draft → active → archived. A sub-pattern for specs and RFCs. |
| [co-located.md](co-located.md) | Docs next to the code. Best for module and service docs. |
| [per-service-repo.md](per-service-repo.md) | Docs in each repo plus a central portal. For polyrepo organizations. |
| [sequential-and-dated.md](sequential-and-dated.md) | Numbered and dated records. For ADRs, postmortems and meetings. |
| [by-version.md](by-version.md) | Docs per version. Only when several versions are live. |
| [flat-with-metadata.md](flat-with-metadata.md) | Flat folder + tags. For small sets and wikis. |
| [hybrid.md](hybrid.md) | Combining models, one dimension per level. What most mature projects use. |
