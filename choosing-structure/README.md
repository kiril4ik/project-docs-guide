# Choosing a Structure

> **What:** How to pick the right doc types, organizing model and storage for *your* project, and how to change course later.
> **Read when:** you're starting docs for a project, or you suspect your current structure doesn't fit.

## Pages

| Page | Use it to | Time |
|---|---|---|
| [decision-guide.md](decision-guide.md) | Answer 8 questions and get a recommended structure (decision tree + scoring matrix) | 10 min |
| [scenarios.md](scenarios.md) | Find your project shape and copy the recommended setup | 5 min per scenario |
| [evolving-structure.md](evolving-structure.md) | Know when to restructure and do it without breaking links | 8 min |

## The short version

1. **List your audiences** ([audiences](../foundations/audiences.md)).
2. **List the doc types you actually need now** ([doc-types catalog](../doc-types/README.md)). Not "someday".
3. **Pick the primary dimension** by how readers search ([dimensions](../organizing/dimensions.md)).
4. **Pick storage** per doc type ([storage-locations](../organizing/storage-locations.md)).
5. **Copy the matching tree** ([folder-structures](../organizing/folder-structures.md)).
6. **Write the rules** in the docs index, and revisit them every 6–12 months.
